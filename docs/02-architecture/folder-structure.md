## Naming Conventions

| Thing | Convention | Example |
|---|---|---|
| Component files | PascalCase | `HeroSection.tsx` |
| Utility files | camelCase | `formatDate.ts` |
| Page files | lowercase (`page.tsx`) | `app/(site)/about/page.tsx` |
| CSS classes | kebab-case (Tailwind) | `font-display`, `text-brand-500` |
| Payload collections | PascalCase singular | `Team.ts`, `Projects.ts` |
| Environment variables | SCREAMING_SNAKE_CASE | `DATABASE_URI`, `PAYLOAD_SECRET` |
| Git branches | kebab-case with prefix | `feat/team-page`, `fix/nav-mobile` |

## Route Group Strategy

Two route groups keep the CMS admin and the public site cleanly separated:

- `(site)` — All public-facing pages share the site layout (header, footer)
- `(payload)` — The Payload admin panel has its own isolated layout

This means `/admin` never accidentally inherits the site header or global styles.

## Import Aliases

Configured in `tsconfig.json`:

```json
{
  "paths": {
    "@/*": ["./src/*"],
    "@/components/*": ["./src/components/*"],
    "@/lib/*": ["./src/lib/*"],
    "@/styles/*": ["./src/styles/*"],
    "@/types/*": ["./src/types/*"],
    "@/variants/*": ["./src/variants/*"]
  }
}
```

Always use `@/` aliases. Never use relative paths that traverse more than one level (`../../`).
